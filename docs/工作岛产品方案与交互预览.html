一条完整工作路径

把文字、链接或文件放到灵动岛 → 选择“先存待办”或一个常用处理方式 → 后台处理 → 灵动岛显示完成提醒 → 点开预览、复制、打开结果；需要写回飞书时，再执行对应动作。

这一层负责什么对你意味着什么
本机灵动岛拖放、消息、阅读、临时待办、提醒和结果入口鼠标移开收起，移回展开；保留阅读页码，不占桌面大块区域。
任务队列与执行器统一记录排队、运行、待确认、完成、失败；按明确版本调用工具或 Skill一次设置“整理客户反馈”要求，以后直接选；失败可重试，完成后有结果。
虚实中台公司入口、可见卡片定义、公司 Skill 目录、个人配置和可选云端任务服务复用已有工作入口；首页 DIY 和岛内 DIY 可以对应，但权限仍按本人核验。
飞书经本人授权的资料、文档、表格和可选待办同步结果可回到原工作资料；点卡片打开原来源，避免另造一套公司资料库。

DIY 我的灵动岛卡片

设置里选择卡片，拖动排序，设置精简/展开显示和是否参与轮播。先提供“本周计划”“我的 OKR”“待办”“AI 任务”“常用入口”；再接本人有权查看的数据组件。

  • 本周计划：显示本周范围、前三项计划、来源和更新时间。你目前的来源要求是上一周飞书汇报里的“下周工作计划”。来源未读到就显示未接入，不生成假计划。
  • DIY 的边界：允许选字段、排序和显示方式；不允许注入脚本、SQL、任意外部请求或修改核心接收逻辑。Agent 仅改受控外观配置。
  • 权限与刷新：同事只看自己的授权数据。未授权、过期或读取失败明确提示；缓存显示“上次更新”，不把无权限和无数据都显示成 0。默认低频刷新，打开卡片时按需刷新。
  • 隐私：锁屏隐藏内容；可选择紧凑状态只显示数量。公司与部门数据权限不因放进灵动岛而扩大。

随手处理、后台完成与 20 分钟提醒

功能第一版行为验收
常用处理方式岗位模板保存工具/Skill、版本、输入类型、输出要求及执行位置。先做“反馈归纳”“文章提炼”两个可检查的入口。重复处理不用重写提示；结果能回溯输入与所用版本，识别不确定内容。
后台执行接收成功后生成任务编号；队列与执行分开。先接一种经过验证的执行器，再扩展本机工具或云端模型。只接受成功回调加实际结果才显示完成；重复回调不重复提醒，取消与失败不冒充完成。
待办与时间文字、链接、文件可先存待办；单项时间覆盖全局默认，默认建议放入后 20 分钟。应用重启后待办还在；同一到期事项只提醒一次。休眠后或应用退出时不承诺准时弹出，下次打开补提醒。
结果去向先在岛内预览、复制或打开本地结果；写飞书文档、建飞书任务作为独立授权的后续动作。普通“处理材料”不等于自动发消息、邮件或改公司数据；结果不会自动对同事共享。

材料拖入后只保存本次主动提交的内容和必要引用；聊天接收仍保持正文只在内存，不自动把聊天历史变成任务存档。文件默认保留原位置；若后续需要上传，会明确执行位置和目标。

目前核实了什么，缺什么

  • 已有：融合版采用现有原生灵动岛外壳；飞书消息可按规则进入岛内。真实只读接收已验证过四条双通道消息；最新全岛内版本另做合成与界面检查，不把历史双通道结果冒充新版本真实验收。
  • 中台首页：2026-10-20 通过 virxact MCP 读取本人首页定义，版本 164。“本周计划 · 周报来源”实际是 notice 提示，注明汇报正文暂未接入。固定“周节奏”组件不是动态本周工作计划。
  • 公司 Skill：市场能列出 Skill 和版本；已看到飞书文档转公众号、虚实报销、虚实网页设计、虚实 PPT、物理驱动的品牌动效。市场存在不代表桌面已具备后台执行它们的能力；两个材料模板也不能冒充市场已有同名工具。
  • 身份：中台应用开发约定明确：网页的公司登录身份与飞书数据授权分开。桌面需要受支持的本人登录/配对机制；当前没有核实可直接给原生应用使用的中台委托读取接口。不能抓 cookie、复用你的账号或伪造登录头。
  • 飞书接入：现有消息应用是只读。文档写回、任务同步需要分别核实数据访问与最小权限，不能沿用消息只读授权直接写。
  • 长期后台：中台服务默认无人使用会休眠，长期任务需明确配置与容量。现有每人服务数量、内存和 CPU 限额不适合直接塞进重型模型；任务服务调用外部执行器，不在容器里运行大模型。

依据：本轮 virxact MCP 的 get_app_guide、get_page（仅定义）、get_spec（week）、list_skills；未修改你的中台首页，未读取周报或文件正文。飞书任务能力以官方创建任务文档为对接核验入口；本轮未申请新权限或创建任务。

建议按这个顺序开发

  1. 先把本机工作台做稳：全岛内消息、移出收起、阅读位置、拖放接收、待办与 20 分钟提醒。用合成资料验证，不上传真实公司文件。
  2. 接一个真实 AI 闭环：选一种可用执行器，跑“反馈归纳”或“文章提炼”，验证后台状态、取消、失败、结果与完成提醒。执行器账号、调用费用与文件边界需落实。
  3. 接个人卡片：优先本周计划与 OKR；先打通本人身份和真实来源，再开放 DIY。计划正文未接入时保留飞书入口，不用占位文字冒充真实数据。
  4. 再同步飞书：按明确授权添加飞书任务、文档写回与多端状态；公司服务器只存应用自己的任务与个人配置。双方仍分别确认同一 GitHub 源码版本，协作面板不承担产品上线。

当前交付：本机消息阅读改动与离线方案/动效预览。待办、后台 AI、周报计划读取、卡片 DIY、飞书写回和原生文件吞噬动效仍是待开发项，没有接入生产，也没有恢复定时发布任务。

需求原话与归属

以下三项由宰治转述为柚子提出；这是需求来源记录，不冒充柚子在面板里的本人操作。

一个是随手处理材料。把文字、文件放进去，调用已有的AI工具和Skill，比如整理客户反馈、提炼文章要点。不同岗位可以接自己常用的功能，不用每次重新写要求。

第二个是后台处理和完成提醒。任务交出去之后，自己继续干别的，做好了灵动岛提醒一下，点开就能拿结果，不用反复切回去看。

第三个是临时待办和定时提醒。正在忙一件事，临时又来了另一件事，可以先把相关文字、链接或文件拖进去存成待办，继续做手头的事。提醒时间可以单独设，也可以在设置里统一设好，比如每个任务放进去20分钟后提醒。忙完了可以自己去看待办，没顾上处理的话，到时间也会提醒，防止忘了。
