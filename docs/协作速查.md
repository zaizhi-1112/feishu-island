# 一切在岛协作速查

当前开发版本为 0.12.14 build108；实际公开包及网站状态以验证记录为准。原生融合应用位于 `apps/island`，产品网页位于 `apps/island/Distribution/site`；`apps/danmu` 与 2026-10-19 导入说明保留历史来源，不是当前实现待办。

## 第一次接手

> 请克隆 https://github.com/zaizhi-1112/feishu-island，先读根目录 AGENTS.md、README.md、docs/验证记录.md 和相关子目录规则。核对 GitHub 默认分支、最新 Release 及正在进行的 PR，确认实际开发基线。使用我自己的 GitHub 和飞书身份，先跑相关合成检查；不要读取真实消息、安装后台组件或代替真人批准。

源码已公开，读取不需要邀请。代码提交、公司服务与飞书授权分别使用各自的账号，不共享 token。历史文档中的私有仓库状态、融合未完成和旧验证数字只描述当时。

## 开始一个功能

每项任务写清现在的行为、期望的行为和验收标准。在独立 `codex/任务名` 分支实现；不要在其他仍工作的任务目录里混改。

> 请处理这项需求，先核对当前实现和最新共同基线。运行与改动相关的检查，完成后同步任务分支和 PR，用中文说明用户影响、验证与未验证项。不要提交真实消息、密钥、本机材料或日志，不 force push。

## 合入共同基线

build94 的完整源码与仓库首页通过 [PR #11](https://github.com/zaizhi-1112/feishu-island/pull/11) 更新共同基线。2026-10-29，宰治明确同意“本次由我批准，合入主分支”，仅本次采用其单独批准；不代表柚子已投票。合并状态可从 PR 与 main 提交核对，不通过更换默认分支掩盖未合入的状态。

沿用双方对同一版本分别批准的约定，再通过明确的 PR 合入 `main`。代码合并、安装包发布、官网更新和实际安装分别核对；Agent 不代人投票。仓库是否有强制保护，以 GitHub 当前设置为准，不沿用旧私有仓库的套餐错误来推断现在的状态。

## 每次发布一并核对

1. **源码**：确认默认分支包含这次已批准的源码；保留提交历史及可回退版本。
2. **仓库首页**：README 的产品名、版本、功能、使用与构建入口正确；右侧 About、官网地址和来源说明保持当前。
3. **安装包**：提高 build 号，完成相应检查与打包审核，用 `apps/island/scripts/release-github-update.py` 发布安装包、签名更新源、安装说明与校验值。仅推送源码不会生成应用更新。
4. **官网**：沿用最新已上线页面，更新包和版本。校验同源下载名为 `一切在岛.dmg`，旧下载链接兼容，等待新发布变成 `live`。
5. **记录**：更新 `docs/验证记录.md` 和相关版本记录；明确哪些是合成检查、真实安装或用户现场确认。旧记录保留日期，不冒充当前状态。

发布当前版本不更改仓库访问范围、公司网页访问范围或飞书权限。主分支合并若需要修改现有批准规则，应由维护者明确决定并同步规则。
