# 两个人和两个 Agent 怎么一起做

## 第一次

把仓库链接交给各自的 Agent，说：

> 请克隆这个私有仓库，先读根目录 AGENTS.md、README.md、docs/融合与协作说明.html 和验证记录。确认登录的是我自己的 GitHub 账号。先运行与我的任务相关的合成测试，不读取真实飞书消息，不安装或启动后台组件，不直接改 main，不部署。告诉我当前已实现什么、还没实现什么。

同事需要自己的 GitHub 账号并接受邀请；Agent 在同事的机器上使用同事自己的 GitHub 和飞书授权，不能共享你的 token。

## 开始一个功能

先在 Issues 用日常语言写“我要什么、现在怎样、怎样算完成”，再给 Agent：

> 请处理 Issue #编号。从最新 main 创建独立的 codex/任务名 分支；如果另一个 Agent 正在同目录工作，使用独立 Git worktree。先确认已有行为，再做最小修改，运行相关检查。完成后推送这个任务分支并创建 PR，不直接合并或部署。PR 用中文说明用户影响、测试结果和未验证项。不要提交真实消息、密钥或本机日志。

## 看对方的成果

> 请只读检查 PR #编号，说明解决了什么、实际验证了什么、有没有影响接收/授权/隐私或现有界面。不要自动合并，不要运行真实账号或会挡住桌面的测试。有问题写成具体修改建议。

## 合并

你们查看预览，确认功能和核心边界，再明确让 Agent 合并指定 PR。合并代码不等于发布应用；安装包、线上发布和实机验收单独安排。

## 当前融合顺序

1. 明确第一版验收：一个本机接收器；灵动岛列表和可开关的桌面弹幕；不重复提醒。
2. 从同事版结构化接收事件，接入你的透明 Overlay，保留未读复核、分页和队列限制；用合成数据验证。
3. 灵动岛设置控制弹幕开关、暂停与外观；停止接收和静音提醒分别处理，避免含义混淆。
4. 先在专门测试环境演示，再由本人授权做真实私聊、群聊与屏幕场景验收。
5. 网页授权入口与本机授权是否进一步合并另行决定；不自动新增服务器数据传输。

仅“把两个目录放在一个仓库”不代表第 2–4 步已经完成。
