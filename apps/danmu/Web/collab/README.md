# 飞书工作岛 · 一起开发

入口 `/collab/`。无需 GitHub 网页操作，双方各自用公司账号登录。应用仍保持公司登录；只有明确加入的两位成员能读写协作记录。宰治与柚子均为共同负责人，拥有相同项目权限。原弹幕入口仍用 DANMU_OWNER_ID 限制原本人账号，不随项目角色改变。

- 需求：提出人按当前登录身份自动记录，表单和需求卡片明确展示；需求完成不等于版本源码批准。保存描述、进度，点击“交给 Codex”复制任务。
- 版本：发布助手从真实 GitHub PR 同步改动与检查。没有通过检查、冲突或版本过期不能同意。
- 双方同意：绑定具体代码 SHA、主版本 SHA、标题、改动、验证信息。任一变化清空同意。要求修改立即撤销排队。Agent 不能投票。
- 过程：保留讨论、状态变更、两人决策与发布结果。阶段归纳基于这些记录生成，不虚构 Agent 工作进度。
- 版本源码：双方分别同意后，才可把确认的代码合入 GitHub 主版本。面板记录对应提交与结果，不负责产品服务上线或安装包。
- 当前定时检查已关闭；需要手动执行已批准的源码同步，不能宣称点击后立即更新。

`COLLAB_OWNER_ID`、`DANMU_OWNER_ID` 是平台稳定用户 ID；不得用昵称替代。新增伙伴通过申请与负责人确认完成绑定，分享范围只加柚子。发布 capability 只允许同步、领取与报告，不能同意。签名防篡改与重放，持久文件在 `/data/collab`。

本地预览：设置 COLLAB_PREVIEW=1、DANMU_WEB_PREVIEW=1、DANMU_DATA_DIR 指向独立目录，以端口 8772 启动 Web/server.cjs。`?actor=b` 仅在此本地模式中切换合成伙伴。生产拒绝预览。测试：`npm test --prefix apps/danmu/Web`。

源码确认使用 scripts/collab-sync.mjs、collab-envelope.cjs 和 collab-runner.mjs。GitHub 凭证留在本机；结果不明先对账，不盲目重试。完整约定见 docs/面板发布自动化.md。

项目来源明确记录：柚子开发柚子岛（灵动岛），宰治开发飞书弹幕，两个已有项目融合后共同开发。来源补录不伪装成本人在面板或 GitHub 做过操作，未知开发时间不编造。

两位都是共同负责人；尚未绑定的柚子仍须本人首次加入，不能用历史贡献代替登录和审批。原弹幕消息入口不随角色调整开放。
